LAB 11 - คำนวณ Rolling Statistics 5 นาทีล่าสุด

ก่อนหน้า: LAB 10 - สืบค้น Sensor Data ด้วย SQLกลับหน้าแรกถัดไป: LAB 12 - แยก SQLite Write และ Statistics Flow

11.1 แนวคิดของ LAB

LAB นี้คำนวณสถิติจากข้อมูลช่วงเวลาล่าสุด เช่น 5 นาทีล่าสุด แทนการคำนวณจากข้อมูลทั้งหมดใน database

Historical data ทั้งหมด = ภาพรวมระยะยาว
Rolling 5 minutes      = สถานะล่าสุดของระบบ

Rolling Statistics เป็นพื้นฐานของระบบ monitoring เพราะช่วยตอบว่า “ตอนนี้ระบบกำลังมีแนวโน้มอย่างไร” ไม่ใช่แค่ค่า sensor ล่าสุดค่าเดียว

11.2 วัตถุประสงค์

หลังจบ LAB นี้ คุณจะสามารถ:

  • เขียน SQL สำหรับข้อมูล 5 นาทีล่าสุด
  • คำนวณ count, average, min และ max
  • ใช้ Node-RED trigger query เป็นช่วงเวลา
  • แสดงผล statistics บน Dashboard
  • แสดง Historical Data จาก SQLite บน Chart
  • เข้าใจความต่างระหว่าง latest value และ rolling statistics
  • เตรียมแนวคิดสำหรับ Rule & Alert ใน LAB 13

11.4 SQL สำหรับ 5 นาทีล่าสุด

SELECT
  COUNT(*) AS records,
  ROUND(AVG(temp), 2) AS avg_temp,
  MIN(temp) AS min_temp,
  MAX(temp) AS max_temp,
  ROUND(AVG(humi), 2) AS avg_humi,
  MIN(humi) AS min_humi,
  MAX(humi) AS max_humi,
  ROUND(AVG(light), 2) AS avg_light,
  MIN(light) AS min_light,
  MAX(light) AS max_light
FROM sensor_data
WHERE created_at >= datetime('now', '-5 minutes');

ทดสอบจาก command line:

sqlite3 /home/piuser/iot.db "SELECT COUNT(*) FROM sensor_data WHERE created_at >= datetime('now', '-5 minutes');"

11.5 สร้าง Inject Node

ตั้งค่า Inject node:

Name: Every 10 seconds
Repeat: interval
Interval: 10 seconds
Payload: timestamp หรือ empty

Inject node ทำหน้าที่เรียก query ซ้ำอัตโนมัติ ไม่ต้องรอ MQTT message ใหม่ทุกครั้ง

11.6 สร้าง Function เตรียม SQL

เพิ่ม function node ชื่อ:

Prepare Rolling SQL

ใช้โค้ด:

msg.topic = `
SELECT
  COUNT(*) AS records,
  ROUND(AVG(temp), 2) AS avg_temp,
  MIN(temp) AS min_temp,
  MAX(temp) AS max_temp,
  ROUND(AVG(humi), 2) AS avg_humi,
  MIN(humi) AS min_humi,
  MAX(humi) AS max_humi,
  ROUND(AVG(light), 2) AS avg_light,
  MIN(light) AS min_light,
  MAX(light) AS max_light
FROM sensor_data
WHERE created_at >= datetime('now', '-5 minutes')
`;

return msg;

11.8 Format ผลลัพธ์สำหรับ Dashboard

เพิ่ม function node ชื่อ:

Format Rolling Statistics

ใช้โค้ด:

let row = msg.payload[0] || {};

msg.payload =
`Records: ${row.records || 0}\n` +
`Temp avg/min/max: ${row.avg_temp ?? "-"} / ${row.min_temp ?? "-"} / ${row.max_temp ?? "-"}\n` +
`Humi avg/min/max: ${row.avg_humi ?? "-"} / ${row.min_humi ?? "-"} / ${row.max_humi ?? "-"}\n` +
`Light avg/min/max: ${row.avg_light ?? "-"} / ${row.min_light ?? "-"} / ${row.max_light ?? "-"}`;

return msg;

ต่อเข้ากับ Text widget หรือ Template widget

11.9 Query ข้อมูลสำหรับ History Chart

Statistics ให้ค่ารวมเพียงหนึ่ง record แต่ History Chart ต้องใช้ข้อมูลหลาย record เรียงตามเวลา ใช้ SQL ต่อไปนี้:

SELECT
  id,
  created_at AS time_utc,
  temp,
  humi,
  light
FROM sensor_data
WHERE created_at >= datetime('now', '-5 minutes')
ORDER BY created_at ASC;

SQLite node จะคืน msg.payload เป็น Array เรียงจากข้อมูลเก่าไปใหม่

11.10 แปลงข้อมูลสำหรับ Chart

เพิ่ม Function node หลัง SQLite node แล้วแปลงแต่ละ record เป็นหนึ่ง message สำหรับ ui-chart:

const rows = msg.payload;

return [rows.map(row => ({
    topic: "Temperature History DB",
    payload: row.temp,
    timestamp: new Date(
        row.time_utc.replace(" ", "T") + "Z"
    ).getTime()
}))];

created_at ใน LAB 08 เก็บเวลา UTC จึงเติม Z เพื่อบอก JavaScript ว่าค่านี้เป็น UTC จากนั้น Browser จะแสดงเวลาตาม timezone ของผู้ใช้

Debug node ควรแสดงหลาย message โดยแต่ละ message มีรูปแบบดังนี้:

msg.topic     = "Temperature History DB"
msg.payload   = ค่า temperature
msg.timestamp = เวลาในรูป Unix milliseconds

11.12 History และ Live MQTT

Historical Data จาก SQLite และ Live Data จาก MQTT สามารถส่งเข้า Chart เดียวกันได้เมื่อใช้รูปแบบ message เดียวกัน:

SQLite History --------\
                        +--> Temperature Chart
MQTT Live -------------/

รูปแบบกลางที่ทั้งสองเส้นทางต้องสร้างคือ:

msg.payload   = temperature
msg.timestamp = timestamp ในหน่วย milliseconds

สำหรับ Live MQTT สามารถกำหนด timestamp ก่อนส่งเข้า Chart:

msg.timestamp = Date.now();
return msg;

การรวม History กับ Live Data ต้องจัดการข้อมูลซ้ำ การล้าง Chart และความแตกต่างระหว่าง Append กับ Replace จึงให้ส่วนนี้เป็นกิจกรรมเพิ่มเติม ไม่ใช่เงื่อนไขหลักของ LAB

11.13 ตรวจกรณีไม่มีข้อมูล

หยุด simulator แล้วรอเกิน 5 นาที จากนั้น query ใหม่ ผลที่ควรเข้าใจ:

records = 0
avg/min/max อาจเป็น null

นี่คือสัญญาณว่าไม่มีข้อมูลล่าสุด ไม่ใช่ sensor วัดค่าเป็น 0

11.14 ปัญหาที่พบบ่อย

อาการ จุดตรวจ
records เป็น 0 ตลอด simulator ไม่ส่งข้อมูล หรือเวลาระบบผิด
dashboard แสดง undefined ไม่ได้ตรวจ msg.payload[0]
query ช้า database โตมาก หรือไม่มี index เวลา
ค่าเฉลี่ยไม่เปลี่ยน inject interval ไม่ทำงาน
History Chart ไม่แสดง Function ไม่ได้คืน Array ของ messages หรือ timestamp ไม่ใช่ milliseconds
เวลาใน Chart เหลื่อม ไม่ได้ระบุว่า created_at เป็น UTC ก่อนสร้าง JavaScript Date

11.15 เพิ่ม Index เพื่อ Query เร็วขึ้น

ถ้าข้อมูลเริ่มมาก ให้เพิ่ม index:

CREATE INDEX IF NOT EXISTS idx_sensor_data_created_at
ON sensor_data(created_at);

รันจาก command line:

sqlite3 /home/piuser/iot.db "CREATE INDEX IF NOT EXISTS idx_sensor_data_created_at ON sensor_data(created_at);"
