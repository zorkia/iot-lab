15.10 Function Node - Automatic Control

สร้าง Function Node แล้วตั้งชื่อ:

Automatic Control

ใช้โค้ด:

let temp = Number(msg.payload.temp);

let fan_state = context.get("fan_state") || "OFF";

if (temp > 35) {
    fan_state = "ON";
} else if (temp < 30) {
    fan_state = "OFF";
}

context.set("fan_state", fan_state);

msg.payload = fan_state;

return msg;

context.get() ใช้เรียกสถานะเดิม context.set() ใช้บันทึกสถานะใหม่ ทำให้ช่วง:

30-35 °C

15.13 State-change-based Control

ปรับ Function เป็น:

let temp = Number(msg.payload.temp);

let fan_state = context.get("fan_state") || "OFF";
let new_state = fan_state;

if (temp > 35) {
    new_state = "ON";
} else if (temp < 30) {
    new_state = "OFF";
}

if (new_state === fan_state) {
    return null;
}

context.set("fan_state", new_state);

msg.payload = new_state;

return msg;

ผล:

28 → ไม่ส่ง Command
32 → ไม่ส่ง Command
36 → ON
38 → ไม่ส่ง Command
39 → ไม่ส่ง Command
33 → ไม่ส่ง Command
29 → OFF
28 → ไม่ส่ง Command

ระบบส่ง MQTT Command เฉพาะเมื่อเกิด:

OFF → ON
ON → OFF

เรียกว่า State-change-based Control

15.14 ข้อจำกัดของ Initial State

ใน Function มี:

context.get("fan_state") || "OFF"

เมื่อ Node-RED เริ่มทำงานใหม่ ระบบจึงสมมติว่า:

fan_state = OFF

แต่ ESP32 จริงอาจมีสถานะ:

ON

ดังนั้น:

Gateway State

อาจไม่ตรงกับ:

Actual Device State

หรือกล่าวได้ว่า:

Commanded State ≠ Actual State

  • Device Status

  • Offline Detection
  • Reconnection
  • Recovery

15.18 Manual / Auto Mode

ไม่ควรคิดว่าเมื่อมี Automatic Control แล้ว Manual Control ไม่มีประโยชน์ Manual Control ยังจำเป็นสำหรับ:

  • Testing
  • Maintenance
  • Override
  • Troubleshooting

แต่ถ้า Manual และ Automatic Control ส่ง Command พร้อมกัน อาจเกิด:

Manual → OFF

Automatic Rule → ON
