13.1 แนวคิดของ LAB

LAB นี้เป็นจุดเปลี่ยนจากระบบ IoT ที่ทำเพียง Monitoring ไปสู่ระบบที่สามารถ ประมวลผลและตัดสินใจจากข้อมูล จากเดิม:

Sensor → MQTT → Node-RED → Dashboard
                         │
                         └──→ SQLite

ระบบตอบได้เพียง:

"เกิดอะไรขึ้น?"

LAB 13 เพิ่ม Rule Processing:

 MQTT

Node-RED
   ↓
 Rule
   ↓
Status
 ├── NORMAL

13.4 ข้อมูลที่ใช้ทดลอง

MQTT Topic:

pkru/iot/001/data

ตัวอย่าง Payload:

{
  "temp": 32.5,
  "humi": 70,
  "light": 1500
}

LAB นี้ใช้ temp เป็นตัวแปรหลักในการทดลอง Rule Processing กำหนด Rule:

Temperature Status
< 30 °C NORMAL
30-35 °C WARNING
> 35 °C ALERT

สิ่งสำคัญที่ต้องเข้าใจคือ:

Threshold เป็นกฎที่ระบบกำหนดขึ้น ไม่ใช่คุณสมบัติของ Sensor

Sensor มีหน้าที่วัดข้อมูล ส่วน Gateway / Processing Layer มีหน้าที่ตีความข้อมูล

13.5 ทดสอบ MQTT ก่อนสร้าง Rule

เปิด Terminal บน Raspberry Pi:

mosquitto_sub -h localhost -t "pkru/iot/001/data" -v

เปิด Terminal อีกหน้าต่าง

ทดสอบ NORMAL

mosquitto_pub -h localhost \
  -t "pkru/iot/001/data" \
  -m '{"temp":28,"humi":70,"light":1500}'

ผล:

pkru/iot/001/data {"temp":28,"humi":70,"light":1500}

ทดสอบ WARNING

mosquitto_pub -h localhost \
  -t "pkru/iot/001/data" \
  -m '{"temp":32,"humi":70,"light":1500}'

ทดสอบ ALERT

mosquitto_pub -h localhost \
  -t "pkru/iot/001/data" \
  -m '{"temp":38,"humi":70,"light":1500}'

ขั้นตอนนี้ใช้ตรวจสอบ Data Path ก่อนนำ Rule Processing เข้ามาเกี่ยวข้อง

13.7 Temperature Rule

เพิ่ม function node แล้วตั้งชื่อ:

Temperature Rule

ใช้โค้ด:

let temp = Number(msg.payload.temp);

if (temp < 30) {
    msg.status = "NORMAL";
} else if (temp <= 35) {
    msg.status = "WARNING";
} else {
    msg.status = "ALERT";
}

return msg;

ตัวอย่างข้อมูล:

{
  "temp": 32,
  "humi": 70,
  "light": 1500
}

หลังผ่าน Rule:

msg.payload.temp = 32
msg.status = "WARNING"

ดังนั้นระบบเปลี่ยนจาก Raw Data:

temp = 32

เป็นข้อมูลที่ผ่านการตีความแล้ว:

temp = 32
status = WARNING

แนวคิดคือ:

Raw Data
    ↓
Processing
    ↓
Information
    ↓
System State

13.9 แยก Data Flow ตามสถานะ

เพิ่ม switch node:

                     ┌── NORMAL ──→ Debug
                     │
MQTT → JSON → Rule ──┼── WARNING ─→ Debug
                     │
                     └── ALERT ───→ Debug

ตั้ง Property:

msg.status

สร้าง 3 Rules:

== NORMAL
== WARNING
== ALERT

Switch node จะมี 3 Outputs ช่วยให้คุณเห็นว่า Rule ไม่ได้มีหน้าที่เพียงสร้างข้อความสถานะ แต่สามารถใช้กำหนด เส้นทางการทำงานของระบบได้

temp = 28
Status = NORMAL
Alert  = No

temp = 32
Status = WARNING

temp = 38
Status = ALERT
Alert  = Yes

Architecture:

Sensor Data
     ↓
    Rule
     ↓

     ↓
Alert Condition
     ↓

ดังนั้นไม่ควรถือว่าทุก Status คือ Alert Alert เป็นเหตุการณ์ที่เกิดขึ้นเมื่อเงื่อนไขที่กำหนดไว้เป็นจริง

13.12 Sensor Simulator

เพื่อไม่ต้องใช้ mosquitto_pub ส่งค่าทีละค่า สามารถจำลอง Sensor บน Raspberry Pi:

while true
do
    temp=$((25 + RANDOM % 16))

    mosquitto_pub \
        -h localhost \
        -t "pkru/iot/001/data" \
        -m "{\"temp\":$temp,\"humi\":70,\"light\":1500}"

    sleep 2
done

ระบบจะสร้างค่า Temperature แบบสุ่มประมาณ:

25-40 °C

ทุก 2 วินาที Node-RED จะประมวลผลและเปลี่ยนสถานะอัตโนมัติระหว่าง:

NORMAL
WARNING
ALERT

ทำให้สามารถทดลอง Rule Processing แบบ Real-time ได้

13.13 Boundary Testing

การทดสอบ Rule ไม่ควรทดสอบเฉพาะค่าที่อยู่กลางช่วง ต้องทดสอบค่าบริเวณ Boundary ด้วย สำหรับ Rule:

temp < 30       → NORMAL
temp <= 35      → WARNING
temp > 35       → ALERT

ควรทดสอบอย่างน้อย:

temp Expected
29 NORMAL
30 WARNING
35 WARNING
36 ALERT

Boundary Test ช่วยตรวจสอบความผิดพลาดจากการใช้:

<
<=
>
>=

ผิดตำแหน่ง

เมื่อใช้ Rule:

> 35  → ALERT

ระบบจะเปลี่ยนสถานะ:

WARNING
ALERT
WARNING
ALERT
WARNING
ALERT

สถานะจึงเปลี่ยนกลับไปกลับมาบริเวณ Threshold เรียกว่า:

State Flapping

ปัญหานี้สามารถแก้ด้วยแนวคิด เช่น Hysteresis แต่ยังไม่จำเป็นต้องนำมาเป็นแกนหลักของ LAB 13 สามารถใช้เป็น Advanced Exercise ได้
