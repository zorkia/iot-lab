ความสัมพันธ์กับเอกสารอื่น

เอกสารนี้เป็นพื้นฐานสำหรับการเปิดบริการบน kathu ผ่าน Internet โดยใช้ Cloudflare Tunnel

รูปแบบ Tunnel ที่ใช้ในเอกสาร

เอกสารชุดนี้ใช้ Locally-managed Tunnel โดยเก็บ ingress configuration ไว้ที่ /etc/cloudflared/config.yml เพื่อให้คุณเห็นและตรวจสอบ routing ได้จาก command line โดยตรง ส่วน Cloudflare แนะนำ Remotely-managed Tunnel สำหรับระบบทั่วไปที่ต้องการจัดการ configuration ผ่าน Dashboard, API หรือ Terraform

เอกสารอ้างอิง: Locally-managed tunnels

1. ตรวจสอบ Origin Web Service

ไฟล์นี้ถือว่า web service ถูกติดตั้งไว้แล้ว ขั้นนี้ตรวจเพียงว่า origin ที่จะเอาเข้า Cloudflare Tunnel ทำงานจริงบน Pi

ตรวจ service ที่ใช้จริง เช่น nginx หรือ service อื่น:

systemctl status <WEB-SERVICE> --no-pager

ทดสอบจาก Pi โดยตรง:

curl http://localhost

หรือถ้า origin อยู่ port อื่น ให้เปลี่ยน port ให้ตรงกับบริการจริง:

curl -I http://localhost:<PORT>

ถ้ายังไม่มี web service ให้ติดตั้งและตั้งค่าใน Knowledge Base หรือ Lab ของบริการนั้นก่อน แล้วจึงกลับมาทำเฉพาะส่วน Cloudflare ในไฟล์นี้

2. ติดตั้ง cloudflared

สร้าง directory สำหรับ key:

sudo mkdir -p --mode=0755 /usr/share/keyrings

เพิ่ม Cloudflare signing key:

curl -fsSL https://pkg.cloudflare.com/cloudflare-main.gpg \
  | sudo tee /usr/share/keyrings/cloudflare-main.gpg >/dev/null

เพิ่ม Cloudflare repository:

echo "deb [signed-by=/usr/share/keyrings/cloudflare-main.gpg] https://pkg.cloudflare.com/cloudflared any main" \
  | sudo tee /etc/apt/sources.list.d/cloudflared.list

ติดตั้ง:

sudo apt update
sudo apt install cloudflared -y

ตรวจสอบ:

cloudflared --version

ตัวอย่างผลที่ได้:

cloudflared version 2026.9.3

3. ทดลอง Quick Tunnel

ขั้นนี้ยังไม่ต้องมี Domain หรือ Cloudflare Account

รัน:

cloudflared tunnel --url http://localhost:80

Cloudflare จะสร้าง URL ชั่วคราว เช่น:

https://xxxxx.trycloudflare.com

นำ URL ไปเปิดจาก Internet เช่น โทรศัพท์ที่ใช้ 4G/5G

ถ้าเห็นหน้า Web ของ Pi แสดงว่า

Pi
 │
 └── Internet
       │
       └── Cloudflare Tunnel

สามารถทำงานผ่านเครือข่ายปัจจุบันได้

ข้อควรทราบ:

Quick Tunnel

  • URL ถูกสุ่ม
  • URL ไม่ถาวร
  • เมื่อหยุด cloudflared URL จะหยุดทำงาน
  • เหมาะสำหรับทดลองเท่านั้น

หยุดด้วย:

Ctrl + C

4. Login Cloudflare

ขั้นต่อไปเป็นการสร้าง Named Tunnel แบบถาวร

ต้องมี:

  • Cloudflare Account
  • Domain ที่จัดการ DNS ด้วย Cloudflare

Login:

cloudflared tunnel login

คำสั่งจะแสดง URL จากนั้น:

  1. เปิด URL ด้วย Browser
  2. Login Cloudflare
  3. เลือก Domain
  4. กด Authorize

จากนั้นตรวจสอบ:

ls -la ~/.cloudflared/

ควรพบไฟล์ ~/.cloudflared/cert.pem

WARNING

cert.pem เป็น credential ห้ามแจกหรือเผยแพร่

5. สร้าง Named Tunnel

ตัวอย่างสร้าง Tunnel ชื่อ:

kathu

คำสั่ง:

cloudflared tunnel create kathu

ตัวอย่างผล:

Created tunnel kathu with id

TUNNEL_UUID

และจะสร้าง credentials file:

~/.cloudflared/TUNNEL_UUID.json

WARNING

ไฟล์ .json เป็น credential เช่นกัน ห้ามเผยแพร่

6. ตรวจสอบ Tunnel

cloudflared tunnel list

ตัวอย่าง:

ID                                    NAME
TUNNEL_UUID kathu

ดูรายละเอียด:

cloudflared tunnel info kathu

7. สร้าง DNS สำหรับ Tunnel

ต้องการ:

pi.vodun.cc

ให้ชี้ไปยัง Tunnel ชื่อ kathu

ใช้:

cloudflared tunnel route dns kathu pi.vodun.cc

ถ้าสำเร็จจะพบข้อความประมาณ:

Added CNAME pi.vodun.cc which will route to this tunnel

โครงสร้าง:


pi.vodun.cc
       │
       ▼

       │
       ▼

8. สร้าง Cloudflare Tunnel Configuration

ระบบ kathu กำหนดให้ systemd ใช้ config กลางที่:

/etc/cloudflared/config.yml

สร้าง directory และเปิดไฟล์:

sudo mkdir -p /etc/cloudflared
sudo nano /etc/cloudflared/config.yml

ใส่:

tunnel: TUNNEL_UUID
credentials-file: /home/piuser/.cloudflared/TUNNEL_UUID.json

ingress:
  - hostname: pi.vodun.cc
    service: http://localhost:80

  - service: http_status:404

หมายเหตุ:

Tunnel UUID ของแต่ละเครื่องไม่เหมือนกัน ต้องใช้ UUID ที่ได้จาก:

cloudflared tunnel list

9. ตรวจสอบ Configuration

cloudflared --config /etc/cloudflared/config.yml tunnel ingress validate

ถ้าถูกต้องควรได้:

Validating rules from /etc/cloudflared/config.yml
OK

ตรวจว่า hostname จับคู่กับ ingress rule ที่ถูกต้อง:

cloudflared --config /etc/cloudflared/config.yml \
  tunnel ingress rule https://pi.vodun.cc

10. ทดลองรัน Named Tunnel

11. หยุดการทดสอบ Foreground

กด:

Ctrl + C

เมื่อหยุดคำสั่งนี้ Tunnel จะหยุด

ดังนั้นสำหรับใช้งานจริงต้องทำเป็น systemd service

12. ติดตั้ง cloudflared เป็น Service

ติดตั้ง service โดยระบุ config ที่ระบบจะใช้งานจริง:

sudo cloudflared \
  --config /etc/cloudflared/config.yml \
  service install

จากนั้นเปิด service:

sudo systemctl enable --now cloudflared

13. ตรวจสอบ Service

systemctl status cloudflared --no-pager

ควรพบ:

Active: active (running)

ตรวจคำสั่งที่ systemd ใช้เริ่ม service:

systemctl cat cloudflared

ใน ExecStart ต้องพบ:

--config /etc/cloudflared/config.yml

หากไม่พบ path นี้ อย่าแก้ config ต่อจนกว่าจะยืนยันว่า service ใช้ไฟล์ใด

ตรวจ Tunnel:

cloudflared tunnel info kathu

14. ทดสอบหลังติดตั้ง Service

โดยไม่ต้องรัน:

cloudflared --config /etc/cloudflared/config.yml tunnel run kathu

ให้เปิด:

https://pi.vodun.cc

ถ้าเข้าได้ แสดงว่า systemd service ทำงานถูกต้อง

15. ทดสอบหลัง Reboot

sudo reboot

หลัง Pi boot เสร็จ ไม่ต้องรัน cloudflared ด้วยตนเอง

ทดลองเปิด:

https://pi.vodun.cc

ถ้าเข้าได้ แสดงว่าระบบทำงานอัตโนมัติสมบูรณ์

20. สิ่งที่ Cloudflare Tunnel ไม่ต้องใช้

ไม่ต้องมี:

  • Public IPv4
  • Fixed IP
  • Dynamic DNS
  • Port Forwarding
  • สิทธิ์ตั้งค่า Router
  • Inbound Port จาก Internet

เพราะ cloudflared เป็นฝ่ายสร้าง connection ออกจาก Pi:

Raspberry Pi
     │
     │ Outbound Tunnel
     ▼
 Cloudflare
     ▲
     │ HTTPS
     │
 Internet User

ดังนั้นสามารถใช้ได้แม้ Pi อยู่หลัง:

  • NAT
  • CGNAT
  • 4G/5G Router
  • Wi-Fi มหาวิทยาลัย

ตราบใดที่เครือข่ายนั้นอนุญาตให้ cloudflared เชื่อมต่อออกไปยัง Cloudflare

21. Quick Tunnel vs Named Tunnel

หัวข้อ Quick Tunnel Named Tunnel
วิธีเริ่ม cloudflared tunnel --url http://localhost:80 ใช้ Named Tunnel และไฟล์ /etc/cloudflared/config.yml
Public hostname สุ่มเป็น xxxxx.trycloudflare.com กำหนดเอง เช่น pi.vodun.cc
อายุการใช้งาน ชั่วคราว หยุดเมื่อ Process หยุด ทำงานต่อเนื่องผ่าน systemd
เหมาะกับ ทดลอง, ตรวจ Network, Demo ชั่วคราว Lab จริง, Dashboard, IoT Web Application, Production/Test Server

23. สำหรับ Pi หลายเครื่อง

สามารถใช้ Domain เดียว แล้วแยก subdomain:

Hostname Tunnel Raspberry Pi
pi.vodun.cc kathu Pi kathu
kata.vodun.cc kata Pi kata
karon.vodun.cc karon Pi karon
kathu.vodun.cc kathu Pi kathu

ตัวอย่าง:

Internet → Cloudflare → Hostname → Tunnel → Raspberry Pi

แต่ละ Pi สามารถอยู่คนละ Network ได้ ตัวอย่าง:

Raspberry Pi Network
kathu University Wi-Fi หรือ Home Internet
kata University LAN
karon 4G Router

ไม่จำเป็นต้องอยู่ LAN เดียวกัน

ข้อควรระวังด้าน Security

ห้ามเผยแพร่:

  • ~/.cloudflared/cert.pem
  • ~/.cloudflared/TUNNEL_UUID.json

อย่านำไฟล์เหล่านี้ขึ้น:

  • GitHub
  • Google Drive แบบ Public
  • Web Server
  • ระบบแชร์ไฟล์สาธารณะ
  • อย่าส่งให้กลุ่มอื่น

Cloudflare Tunnel ทำให้ Web Service เข้าถึงจาก Internet ได้ ดังนั้น Application ที่มีความสามารถควบคุมอุปกรณ์หรือข้อมูลสำคัญ ควรเพิ่ม Authentication/Cloudflare Access

โดยเฉพาะ:

  • Node-RED Editor
  • Admin Page
  • Device Control
  • MQTT Management Interface

ไม่ควรเปิด Public โดยไม่มี Authentication
