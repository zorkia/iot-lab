ข้อดี:

  • ไม่ต้องมี Public IPv4
  • ใช้งานได้หลัง NAT / CGNAT
  • ไม่ต้อง Port Forward TCP/22 ที่ Router
  • Pi กับ Client ไม่ต้องอยู่ Network เดียวกัน
  • ใช้ชื่อ Domain แทน IP
  • Tunnel เป็นการเชื่อมต่อออกจาก Pi ไปยัง Cloudflare

2. ตรวจสอบ SSH Server บน Raspberry Pi

ไฟล์นี้ถือว่า SSH server บน Raspberry Pi ถูกเตรียมไว้แล้ว ขั้นนี้ตรวจเพียงว่า origin สำหรับ Cloudflare Tunnel พร้อมใช้งาน

ตรวจสอบ:

systemctl status ssh --no-pager

ควรพบ:

Active: active (running)

และ:

Server listening on 0.0.0.0 port 22

ทดสอบจาก Pi:

ssh piuser@localhost

ออกจาก SSH:

exit

ถ้า SSH server ยังไม่ทำงาน ให้กลับไปตั้งค่าในส่วน Raspberry Pi/ระบบปฏิบัติการก่อน แล้วจึงกลับมาทำเฉพาะ Cloudflare Tunnel ในไฟล์นี้

4. สร้าง Subdomain สำหรับ SSH

ไม่ควรใช้:

pi.vodun.cc

เพราะเราใช้ hostname นี้กับ Web Server อยู่แล้ว:

pi.vodun.cc
       ↓
http://localhost:80

สร้าง hostname แยกสำหรับ SSH:

ssh.vodun.cc

ใช้ Tunnel kathu ตัวเดิม:

cloudflared tunnel route dns kathu ssh.vodun.cc

ควรได้ข้อความประมาณ:

Added CNAME ssh.vodun.cc which will route to this tunnel

ดังนั้นไม่จำเป็นต้องสร้าง Tunnel ใหม่

5. กำหนด SSH Service ใน Cloudflare Tunnel

ถ้า cloudflared ทำงานเป็น systemd service ให้ตรวจสอบก่อนว่า service ใช้ config ตัวไหน:

systemctl status cloudflared --no-pager

ของระบบตัวอย่างนี้พบว่าใช้:

--config /etc/cloudflared/config.yml

ดังนั้นแก้:

sudo nano /etc/cloudflared/config.yml

ตัวอย่าง:

tunnel: TUNNEL_UUID credentials-file: /home/piuser/.cloudflared/TUNNEL_UUID.json

ingress:

service: http://localhost:80

  • hostname: pi.vodun.cc

service: ssh://localhost:22

  • hostname: ssh.vodun.cc
  • service: http_status:404

      ↓

      ↓

      ↓

8. ป้องกัน SSH ด้วย Cloudflare Access

ก่อนเปิดให้ผู้ใช้หรือผู้ดูแลเชื่อมต่อจาก Internet ต้องสร้าง Cloudflare Access application สำหรับ:

ssh.vodun.cc

ขั้นตอนใน Cloudflare Zero Trust Dashboard:

  1. ไปที่ Access → Applications และเพิ่ม application แบบ Self-hosted
  2. กำหนด hostname เป็น ssh.vodun.cc
  3. สร้าง policy แบบ Allow เฉพาะ email, email domain หรือกลุ่มผู้ใช้ที่อนุญาต
  4. หลีกเลี่ยง policy ที่อนุญาต Everyone
  5. ทดสอบ policy ก่อนแจก SSH configuration ให้ผู้ใช้

เมื่อใช้ cloudflared access ssh ระบบจะเปิด Browser ให้ยืนยันตัวตนกับ Cloudflare Access ก่อนส่งต่อการเชื่อมต่อไปยัง sshd จากนั้นผู้ใช้ยังต้องผ่าน SSH key หรือรหัสผ่านของ Linux อย่าดำเนินการทดสอบจาก Internet หากยังไม่มี Access policy

9. ฝั่ง Client ต้องมี cloudflared

SSH ที่ Publish ผ่าน Cloudflare Tunnel แบบนี้ไม่ได้เชื่อม TCP/22 ของ Pi จาก Internet โดยตรง

ดังนั้น Client ใช้:

OpenSSH
   +
cloudflared

โดย cloudflared ทำหน้าที่เป็น Proxy ให้ SSH

10. ติดตั้งเครื่องมือบน Client

macOS

ถ้ามี Homebrew:

brew install cloudflared

ตรวจสอบ:

cloudflared --version

ดูตำแหน่ง:

which cloudflared

Mac Apple Silicon โดยทั่วไปจะได้:

/opt/homebrew/bin/cloudflared

Windows

เปิด PowerShell หรือ Windows Terminal แล้วตรวจ OpenSSH Client:

ssh -V

ถ้าไม่พบคำสั่ง ssh ให้ติดตั้งจาก Settings > System > Optional features > View features > OpenSSH Client หรือเปิด PowerShell แบบ Administrator แล้วรัน:

Add-WindowsCapability -Online -Name OpenSSH.Client~~~~0.0.1.0

ติดตั้ง cloudflared ด้วย WinGet:

winget install --id Cloudflare.cloudflared --exact

ปิดแล้วเปิด Terminal ใหม่ จากนั้นตรวจสอบ:

cloudflared --version
Get-Command cloudflared
Get-Command ssh

Get-Command cloudflared จะแสดง path ของโปรแกรม ถ้าคำสั่งยังไม่พบ ให้ตรวจว่า WinGet เพิ่ม directory ของ cloudflared เข้า PATH แล้วหรือยัง

11. ทดลอง SSH ครั้งแรก

macOS

ทดสอบโดยยังไม่แก้ ~/.ssh/config:

ssh \
  -o ProxyCommand="/opt/homebrew/bin/cloudflared access ssh --hostname ssh.vodun.cc" \
  piuser@ssh.vodun.cc

Windows

เปิด PowerShell หรือ Windows Terminal แล้วทดสอบโดยยังไม่สร้าง SSH config:

ssh -o "ProxyCommand=cloudflared access ssh --hostname %h" piuser@ssh.vodun.cc

คำสั่งจะเปิด Browser เพื่อ Login ผ่าน Cloudflare Access ก่อน เมื่อผ่าน policy แล้ว ครั้งแรกที่เชื่อมต่อ SSH อาจพบ:

The authenticity of host 'ssh.vodun.cc' can't be established.

ตรวจสอบ fingerprint แล้วตอบ:

yes

จากนั้น:

piuser@ssh.vodun.cc's password:

ใส่ password ของ user piuser บน Raspberry Pi

ถ้าสำเร็จจะเข้าสู่:

piuser@kathu:~ $

12. ทำให้คำสั่งสั้นลงด้วย SSH config

macOS

ไม่ควรต้องพิมพ์คำสั่งยาวทุกครั้ง

สร้าง/แก้:

nano ~/.ssh/config

เพิ่ม:

Host kathu
    HostName ssh.vodun.cc
    User piuser
    ProxyCommand /opt/homebrew/bin/cloudflared access ssh --hostname %h

จากนั้นใช้งานเพียง:

ssh kathu

แทน:

ssh \
  -o ProxyCommand="/opt/homebrew/bin/cloudflared access ssh --hostname ssh.vodun.cc" \
  piuser@ssh.vodun.cc

Windows

สร้าง directory .ssh และเปิดไฟล์ config จาก PowerShell:

New-Item -ItemType Directory -Force "$HOME\.ssh"
notepad "$HOME\.ssh\config"

ไฟล์จริงอยู่ที่:

C:\Users\ชื่อผู้ใช้\.ssh\config

ชื่อไฟล์ต้องเป็น config โดยไม่มี .txt เพิ่มท้ายไฟล์ แล้วใส่:

Host kathu
    HostName ssh.vodun.cc
    User piuser
    ProxyCommand cloudflared access ssh --hostname %h

จากนั้นใช้งานด้วยคำสั่งเดียวกัน:

ssh kathu

ถ้า Windows แจ้งว่าไม่พบ cloudflared ใน ProxyCommand ให้ใช้ Get-Command cloudflared หา path แล้วแทนชื่อโปรแกรมด้วย path เต็ม เช่น:

ProxyCommand "C:\Program Files\cloudflared\cloudflared.exe" access ssh --hostname %h

ใช้ path ที่ตรวจพบบนเครื่องจริง ตัวอย่างข้างต้นไม่ใช่ตำแหน่งบังคับของ WinGet

14. ตรวจสอบปัญหาฝั่ง Windows

ตรวจว่า OpenSSH และ cloudflared อยู่ใน PATH:

Get-Command ssh
Get-Command cloudflared

ทดสอบ Cloudflare Access แยกจาก SSH:

cloudflared access ssh --hostname ssh.vodun.cc

ตรวจการเชื่อมต่อ HTTPS ไปยัง Cloudflare Edge:

Test-NetConnection ssh.vodun.cc -Port 443

ดูรายละเอียดการทำงานของ OpenSSH และ ProxyCommand:

ssh -vvv kathu

ตรวจว่า OpenSSH อ่าน config ใดอยู่:

ssh -G kathu | Select-String "hostname|user|proxycommand"

ปัญหาที่พบบ่อย:

อาการ จุดตรวจ
ssh ไม่พบ ติดตั้ง OpenSSH Client แล้วเปิด Terminal ใหม่
cloudflared ไม่พบ ตรวจ Get-Command cloudflared และ PATH
เปิด Browser ไม่ได้ รัน cloudflared access ssh --hostname ssh.vodun.cc แยก
config ไม่ทำงาน ตรวจชื่อไฟล์ว่าเป็น config ไม่ใช่ config.txt
Access denied ตรวจ Cloudflare Access application และ policy

18. สิ่งที่ไม่ต้องทำ

ไม่ต้องเปิด:

  • TCP/22 บน Router

ไม่ต้องทำ:

  • Port Forwarding

ไม่ต้องมี:

  • Public IPv4
  • Static Public IP
  • DDNS

และไม่จำเป็นต้องใช้:

ssh piuser@192.168.x.x

เมื่อเชื่อมจาก Internet

19. Security

Cloudflare Tunnel ไม่ได้หมายความว่าไม่ต้องรักษาความปลอดภัย SSH

อย่างน้อยควร:

  • ใช้ password ที่แข็งแรง
  • หรือใช้ SSH Public Key แทน password
  • ไม่ใช้ root login
  • เก็บ Tunnel credential ให้เป็นความลับ

ไฟล์สำคัญที่ห้ามเผยแพร่:

  • /home/piuser/.cloudflared/TUNNEL_UUID.json
  • ~/.cloudflared/cert.pem

สำหรับระบบที่เปิดให้ผู้ใช้เข้าจาก Internet ต้องตรวจว่า Cloudflare Access application และ Allow policy ยังทำงานอยู่เสมอ ควรใช้ SSH Public Key แทนรหัสผ่านเมื่อพร้อม และยกเลิกสิทธิ์ Access เมื่อผู้ใช้ไม่จำเป็นต้องเข้าเครื่องแล้ว
