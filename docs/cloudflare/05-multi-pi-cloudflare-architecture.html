Multi-Pi Cloudflare Architecture

ก่อนหน้า: 04 - Root Domain และ WWW Redirectกลับหน้าแรก

แนวทางจัดการ Raspberry Pi หลายเครื่องที่อยู่ต่างสถานที่และต่างเครือข่าย แต่ใช้ subdomain ภายใต้โดเมน vodun.cc ร่วมกัน โดยไม่ต้องมี Public IPv4 หรือทำ Port Forwarding

ภาพรวม

                    Internet
                       |
                  Cloudflare
                       |
                    vodun.cc
                       |
        +--------------+--------------+
        |              |              |
 ranee.vodun.cc  arjun.vodun.cc  kata.vodun.cc
        |              |              |
 Tunnel: ranee   Tunnel: arjun   Tunnel: kata
        |              |              |
      RPi #1          RPi #2          RPi #3
     Location A      Location B      Location C

Raspberry Pi แต่ละเครื่องไม่จำเป็นต้องอยู่ LAN เดียวกัน ขอเพียงเชื่อมต่อ Internet ได้ และ cloudflared สามารถสร้าง outbound connection ไปยัง Cloudflare

หนึ่ง Pi ต่อหนึ่ง Tunnel

แนะนำให้สร้าง Cloudflare Tunnel แยกสำหรับ Raspberry Pi แต่ละเครื่อง:

Cloudflare Account
|
+-- Tunnel: ranee
|      +-- Pi: ranee
|
+-- Tunnel: arjun
|      +-- Pi: arjun
|
+-- Tunnel: kata
|      +-- Pi: kata
|
+-- Tunnel: karon
|      +-- Pi: karon
|
+-- Tunnel: kathu
       +-- Pi: kathu

ข้อดี:

  • ตรวจสถานะและแก้ปัญหาเป็นรายเครื่อง
  • ปิดหรือย้ายเครื่องหนึ่งได้โดยไม่กระทบเครื่องอื่น
  • ถอนสิทธิ์ Tunnel เฉพาะเครื่องได้
  • แยก credential และลดผลกระทบเมื่อ credential เครื่องหนึ่งรั่ว
  • เหมาะกับ Lab ที่แจก Raspberry Pi ให้ผู้ใช้หลายคน

หนึ่ง Pi ใช้หลาย Subdomain

Tunnel หนึ่งตัวสามารถกำหนด ingress หลาย hostname เพื่อส่งไปยังหลายบริการบน Pi เดียวกัน

ตัวอย่างเครื่อง ranee:

Public hostname Origin บน Pi
ranee.vodun.cc Nginx http://localhost:80
node-red-ranee.vodun.cc Node-RED http://localhost:1880
ssh-ranee.vodun.cc SSH ssh://localhost:22

รูปแบบเดียวกันใช้กับเครื่องอื่นได้ เช่น:

Raspberry Pi Web Node-RED SSH
arjun arjun.vodun.cc node-red-arjun.vodun.cc ssh-arjun.vodun.cc
kata kata.vodun.cc node-red-kata.vodun.cc ssh-kata.vodun.cc

Naming Convention

ประเภท รูปแบบ ตัวอย่าง
Web หลัก {device}.vodun.cc ranee.vodun.cc
Node-RED node-red-{device}.vodun.cc node-red-ranee.vodun.cc
SSH ssh-{device}.vodun.cc ssh-ranee.vodun.cc
Tunnel {device} ranee
Setup AP {device}-setup ranee-setup

ใช้ชื่อ device เดียวกันกับ hostname และ Tunnel เมื่อทำได้ เพื่อให้อ่าน log และ Dashboard ง่าย

การย้าย Pi ไปเครือข่ายใหม่

Raspberry Pi แบบ headless อาจขาดการเชื่อมต่อเมื่อ Known Wi-Fi เดิมไม่มีอยู่ในสถานที่ใหม่:

Known Wi-Fi ไม่พบ
        |
        v
Pi ไม่มี Internet
        |
        v
cloudflared offline
        |
        v
Remote SSH และ Node-RED ใช้ไม่ได้

จึงควรเตรียมทางกู้คืนอย่างน้อยหนึ่งทาง เช่น LAN แบบ DHCP, จอและคีย์บอร์ดชั่วคราว หรือ Setup AP fallback

NetworkManager ไม่เปิด fallback AP ให้อัตโนมัติ

ต้องสร้าง hotspot profile และติดตั้งกลไกตรวจ Known Wi-Fi เช่น systemd service หรือ script ก่อนจึงจะได้พฤติกรรมตาม diagram นี้ หากยังไม่ได้ติดตั้ง ให้ใช้ LAN หรือ local console เป็นช่องทางกู้คืน

ค่าตัวอย่างของ Setup AP:

ค่า ตัวอย่าง
SSID ranee-setup
Pi address 192.168.50.1
Client address 192.168.50.x

เมื่อ Setup AP ทำงาน:

  1. เชื่อม Notebook หรือ Mobile เข้ากับ ranee-setup
  2. เข้า Pi ด้วย ssh piuser@192.168.50.1
  3. ตรวจเครือข่ายที่พบด้วย nmcli device wifi list
  4. เพิ่ม Wi-Fi profile ใหม่
  5. reboot และตรวจว่า Pi กลับมาออนไลน์

เพิ่ม Wi-Fi โดยไม่ใส่รหัสผ่านไว้ใน command history:

sudo nmcli --ask device wifi connect "Hotel-WiFi" \
  ifname wlan0 \
  name "Hotel-WiFi"

กำหนดให้เชื่อมอัตโนมัติและตั้ง priority:

sudo nmcli connection modify "Hotel-WiFi" \
  connection.autoconnect yes \
  connection.autoconnect-priority 100

sudo reboot

ถ้า Hotel-WiFi ใช้งานได้ Pi จะเชื่อม Internet และ cloudflared จะกลับมาออนไลน์ ถ้าเชื่อมไม่ได้ กลไก fallback ที่ติดตั้งไว้ต้องกลับมาเปิด Setup AP อีกครั้ง

Ethernet ใช้ DHCP

แนะนำให้ปล่อย eth0 รับค่าจาก DHCP แทนการกำหนด maintenance IP แบบคงที่:

Internet
   |
 Router
   |
   | DHCP
   v
 eth0
   |
 Raspberry Pi

ข้อดี:

  • นำ Pi ไปเสียบ Router หรือ Switch แห่งใหม่ได้ง่าย
  • ลดปัญหา static IP อยู่คนละ subnet
  • ใช้ LAN ออก Internet ได้โดยไม่แก้ configuration รายสถานที่
  • แยกบทบาท LAN ออกจาก Wi-Fi Setup AP ชัดเจน

ตรวจ interface, address และเส้นทางออก Internet:

nmcli device status
ip -br addr
ip route get 8.8.8.8

ลำดับการเลือกเครือข่าย

Raspberry Pi
|
+-- eth0
|     +-- DHCP
|          +-- มี LAN -> Network / Internet
|
+-- wlan0
      +-- พบ Known Wi-Fi -> Connect
      |
      +-- ไม่พบ Known Wi-Fi -> Setup AP: ranee-setup

ควรกำหนด policy และ metric ให้ชัดเจนเมื่อ LAN กับ Wi-Fi เชื่อมพร้อมกัน ตรวจเส้นทางที่ระบบเลือกจริงด้วย ip route get 8.8.8.8

การควบคุมจากส่วนกลาง

เจ้าของ Cloudflare account และ DNS zone vodun.cc ยังคงควบคุมสิทธิ์จากส่วนกลางได้

ยกเลิก Subdomain

ลบ DNS/hostname เช่น arjun.vodun.cc, node-red-arjun.vodun.cc หรือ ssh-arjun.vodun.cc บริการจะเข้าไม่ได้ผ่านชื่อเดิม แม้ Pi ยังรัน cloudflared

ยกเลิก Tunnel ของเครื่อง

เมื่อออกแบบหนึ่ง Pi ต่อหนึ่ง Tunnel สามารถ revoke หรือลบ Tunnel arjun โดยไม่กระทบ Tunnel ranee และ kata

ปิดเฉพาะบริการ

ลบเฉพาะ route ssh-arjun.vodun.cc เพื่อปิด Remote SSH โดยยังคง Web หรือ Node-RED ของเครื่องเดิมไว้ได้

การแยก Credential

ไม่ควรให้ผู้ใช้ Raspberry Pi ทั่วไปเข้าถึง:

  • Cloudflare account หลัก
  • DNS zone ของ vodun.cc
  • Global API Key
  • credential ของ Tunnel เครื่องอื่น

แต่ละเครื่องควรได้รับเฉพาะ token หรือ credential ที่จำเป็นสำหรับ Tunnel ของตนเอง:

          |             |             |

          |             |             |

Pi แต่ละเครื่องใช้ eth0 แบบ DHCP, จำ Known Wi-Fi ได้หลายเครือข่าย และมี Setup AP เป็นช่องทางกู้คืนเมื่อกลไก fallback ถูกติดตั้งแล้ว ส่วน Cloudflare Tunnel และ credential แยกเป็นรายเครื่อง

สรุป

  1. ใช้โดเมนกลาง vodun.cc และตั้ง subdomain แยกตามอุปกรณ์และบริการ
  2. ใช้หลักหนึ่ง Pi ต่อหนึ่ง Cloudflare Tunnel
  3. แยก Tunnel credential รายเครื่อง
  4. Pi หนึ่งเครื่องใช้หลาย subdomain ได้
  5. ปล่อย eth0 รับ DHCP เพื่อเคลื่อนย้ายข้ามเครือข่ายได้ง่าย
  6. เตรียม Known Wi-Fi หลายเครือข่ายและช่องทางกู้คืนเมื่อ Wi-Fi ใช้ไม่ได้
  7. เมื่อ Internet กลับมา cloudflared จะสร้าง outbound connection ใหม่
  8. เจ้าของโดเมนควบคุม DNS, service route และ Tunnel lifecycle จากส่วนกลาง
แนวคิดสำคัญ

Pi สามารถย้ายไปอยู่ที่ใดก็ได้ตราบใดที่เชื่อมต่อ Internet ได้ ขณะที่เจ้าของโดเมนยังควบคุมสิทธิ์การเข้าถึงจากส่วนกลางผ่าน Cloudflare
