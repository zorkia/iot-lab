Tunnel ที่ใช้

รายการ ค่า
Raspberry Pi hostname ranee
Tunnel name ranee
Tunnel ID ตรวจด้วย cloudflared tunnel list (ตัวอย่างของ ranee: 65e7de67-4655-4ab3-b2b4-5cf25b116a9d)
Tunnel type Locally-managed
Configuration file /etc/cloudflared/config.yml

Locally-managed Tunnel กำหนด Published Applications หรือ ingress routes จากไฟล์ configuration บน Raspberry Pi ไม่ได้แก้รายการ routes จาก Cloudflare Dashboard โดยตรง

ตรวจชื่อและ ID ของ Tunnel ที่มีอยู่ในระบบ:

cloudflared tunnel list

Tunnel ID เป็นค่าประจำ Tunnel แต่ไม่ใช่ credentials อย่างไรก็ตามไม่ควรคัดลอก ID จากเอกสารไปใช้กับเครื่องอื่น ให้ใช้ค่าที่คำสั่งด้านบนแสดงสำหรับ Tunnel ranee

ก่อนเพิ่ม root domain มี Published Applications ดังนี้:

Public hostname Origin service
ranee.vodun.cc http://localhost:80
node-red-ranee.vodun.cc http://localhost:1880
ssh-ranee.vodun.cc ssh://localhost:22

เพิ่ม Root Domain

เปิดไฟล์ configuration บน Raspberry Pi ranee:

sudo nano /etc/cloudflared/config.yml

คงบรรทัด tunnel และ credentials-file เดิมของเครื่องไว้ จากนั้นแก้เฉพาะส่วน ingress โดยเพิ่ม vodun.cc เป็น rule แรก และคง fallback rule ไว้เป็นรายการสุดท้าย:

ingress:
  - hostname: vodun.cc
    service: http://localhost:80

  - hostname: ranee.vodun.cc
    service: http://localhost:80

  - hostname: node-red-ranee.vodun.cc
    service: http://localhost:1880

  - hostname: ssh-ranee.vodun.cc
    service: ssh://localhost:22

  - service: http_status:404
IMPORTANT

http_status:404 ต้องอยู่ท้ายสุด เพราะ cloudflared ตรวจ ingress rules จากบนลงล่าง

ตรวจสอบ Configuration

ตรวจ syntax และลำดับ ingress rules:

sudo cloudflared \
  --config /etc/cloudflared/config.yml \
  tunnel ingress validate

ผลที่ต้องการคือ OK

สร้าง DNS Route

สร้าง DNS route ให้ root domain ชี้เข้า Tunnel ranee:

cloudflared tunnel route dns ranee vodun.cc

เส้นทางที่ได้:

vodun.cc
   │
   ▼

Restart Tunnel

นำ configuration ใหม่ไปใช้:

sudo systemctl restart cloudflared
sudo systemctl status cloudflared --no-pager

สถานะที่ต้องการคือ Active: active (running)

ทดสอบ root domain จากเครื่อง Client:

curl -I https://vodun.cc

ผลที่ได้ควรเดินทางผ่าน Cloudflare และ Tunnel ranee ไปยัง Nginx ที่ localhost:80

สร้าง DNS สำหรับ WWW

ใน Cloudflare Dashboard ไปที่ Domains > vodun.cc > DNS > Records > Add record แล้วกำหนดค่า:

ค่า กำหนดเป็น
Type CNAME
Name www
Target vodun.cc
Proxy status Proxied
TTL Auto

www.vodun.cc ต้องผ่าน Cloudflare Proxy เพื่อให้ Redirect Rule ทำงานที่ Cloudflare Edge

สร้าง WWW Redirect

ใน Cloudflare Dashboard ไปที่ Rules > Redirect Rules > Create new Single Redirect แล้วเลือก Template Redirect from WWW to root

กำหนดค่า:

ค่า กำหนดเป็น
Rule name Redirect www.vodun.cc to vodun.cc
Matching type Wildcard pattern
Request URL https://www.vodun.cc/*
Target URL https://vodun.cc/${1}
Status code 301 - Permanent Redirect
Preserve query string เปิด

ตรวจให้พบข้อความ Rule validation passed แล้วกด Deploy

ผลของ Redirect

Redirect ต้องรักษา path และ query string เดิมไว้:

URL ที่เรียก URL ปลายทาง
https://www.vodun.cc/ https://vodun.cc/
https://www.vodun.cc/test https://vodun.cc/test
https://www.vodun.cc/lab/01 https://vodun.cc/lab/01
https://www.vodun.cc/test?id=123 https://vodun.cc/test?id=123

ทดสอบ Redirect

ทดสอบหน้าแรก:

curl -I https://www.vodun.cc

ควรพบ HTTP status 301 และ header ต่อไปนี้:

location: https://vodun.cc/

ทดสอบ path และ query string:

curl -I "https://www.vodun.cc/test/page?id=123"

ค่า location ควรเป็น https://vodun.cc/test/page?id=123

เหตุผลที่ใช้ Redirect

  • มี Canonical Domain เพียงชื่อเดียว
  • ไม่ต้องดูแลเว็บไซต์ซ้ำสองชุด
  • URL ไม่ซ้ำกัน
  • Nginx ไม่ต้องมีเว็บไซต์สำหรับ www แยก
  • ไม่ต้องเพิ่ม www เป็น ingress rule ของ cloudflared
  • Redirect เกิดที่ Cloudflare Edge ก่อนถึง Raspberry Pi
